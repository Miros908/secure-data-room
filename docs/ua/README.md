# Data Room

Застосунок для обміну файлами. Файли складаються у вкладені папки, ними можна ділитися за публічним посиланням або з конкретним користувачем, ставити строк доступу й відкликати його. Власник бачить, хто відкривав і завантажував файли.

## Деплой

- Фронтенд (Vercel): https://deal-box.vercel.app
- Backend API (Render): https://secure-data-room.onrender.com
- PostgreSQL теж задеплоєний на Render, поруч з API. Публічного URL у бази немає.

## Стек

Монорепозиторій pnpm: Next.js 16 і React 19 на фронті, NestJS 11 API, PostgreSQL 16 і Prisma 7, файли на диску або в Cloudflare R2. Прод: UI на Vercel; API і PostgreSQL на Render.

Бібліотеки й версії — [стек](./stack.md).

## Використання AI

AI використовувався в проєкті як інструмент для прискорення розробки, а не як заміна інженерного проєктування та ухвалення рішень. Архітектура застосунку, модель даних, межі модулів, правила авторизації, вимоги до цілісності даних і основні технічні рішення проєктувалися й перевірялися мною вручну.

Основний робочий процес виглядав так: спочатку формувався конкретний план реалізації задачі з очікуваною поведінкою, обмеженнями та частинами системи, яких це стосується. Після ручної перевірки й коригування плану реалізацію окремих, переважно рутинних задач делегували Cursor з використанням Composer 2.5. Отриманий код після цього проходив ручну перевірку на відповідність архітектурі, бізнес-логіці проєкту та очікуваним edge cases.

Сильніша модель Opus 5 використовувалася окремо як додатковий рівень рев’ю: для рефакторингу, пошуку потенційних дефектів, аналізу складних ділянок коду, перевірки порушень архітектурних меж, дублювання та можливих проблем безпеки. Таким чином, AI застосовувався в кількох ролях — як виконавець заздалегідь визначених задач і як додатковий інструмент code review, — при цьому фінальна відповідальність за архітектуру, коректність логіки та ухвалені технічні рішення лишалася за мною.

## Не реалізовано

- Пошук за текстом усередині файлів
- Один пошук одразу по всіх розшарених кімнатах (вхідні шари лишаються окремим списком)
- Пошук на сервері в журналі, вхідних і вихідних шарах (там і далі фільтр уже завантаженої сторінки)
- Фільтри пошуку за датою, розміром або типом
- Переміщення папок
- Кілька Data Room в одного власника
- Вхід через Google, підтвердження пошти, скидання пароля
- Пагінація listing папки
- Винятки ACL («все в папці, крім цього файла»)
- Фонові воркери, прев’ю, експорт
- Redis, щоб SSE доходив до кожної replica API
- Прибирання сиріт в object storage
- Політика зберігання старих версій файлів і журналу
